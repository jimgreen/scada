SCADA 三个运行模块使用说明

本文说明 scdfe_c 自动采集守护、scdfe_s 主站/服务端测试和 scdfe_t 四遥转发的安装、启动、配置、Web 操作、命令接口和排障方法。

架构准备scdfe_cscdfe_sscdfe_t典型流程接口日志与监控排障

一、模块关系

scdfe_c：现场采集

读取 RTU、通道和四遥定义，按 RTU-通道启动通信线程，使用 client/ 中的主站类采集 YC/YX，并处理 YK/YT。数据库写入由独立写库进程批量完成。

scdfe_s：协议测试

提供 IEC104、Modbus TCP/RTU、CAN、BACnet/IP、OPC UA 的主站/服务端测试页面和单通道命令行入口。主站/客户端类在 client/，服务端/从站类在 server/。

scdfe_t：四遥转发

从 scdfe_c 数据库读取 YC/YX，按独立通道映射对外提供 IEC104 或 Modbus TCP，并把远方 YK/YT 写回 scdfe_c 的点表。

数据流：现场设备 ⇄ client 主站 ⇄ scdfe_c 写库进程 ⇄ SQLite ⇄ scdfe_t 转发；scdfe_s 用于独立协议联调和报文测试。

二、运行准备

  1. Windows 使用 PowerShell，Linux 使用 shell；三套命令都从项目根目录执行。
  2. 使用 Python 3.11，并在项目根目录创建虚拟环境：
python -m venv .venv
# Windows
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
# Linux
.venv/bin/python -m pip install -r requirements.txt

依赖包括 c104、pyModbusTCP、pymodbus、python-can、bacpypes3 和 asyncua。默认数据库为 db/scada.sqlite3，表定义目录为 dbdef/json。需要自定义位置时始终显式传入 --db 和 --schema-dir。

正式现场运行前先备份 SQLite；不要同时启动同一 RTU 的自动通信和人工调试，也不要让两个进程监听同一个 TCP 端口。

三、scdfe_c：自动采集、写库和指令服务

3.1 启动主 Web

# Windows
.\.venv\Scripts\python.exe -B -m scdfe_c.web.server --host 127.0.0.1 --port 8877 --db D:\codex\scada\db\scada.sqlite3
# Linux
.venv/bin/python -B -m scdfe_c.web.server --host 127.0.0.1 --port 8877 --db /var/lib/scada/scada.sqlite3

浏览器打开 http://127.0.0.1:8877/；接口文档为 /api-docs。RTU、通道、协议参数、协议辅助表、YC/YX/YK/YT 和进程监控均在该站点维护。

3.2 启动自动守护

# Windows
.\.venv\Scripts\python.exe -m scdfe_c --db D:\codex\scada\db\scada.sqlite3 --log-dir D:\codex\scada\db\logs
# Linux
.venv/bin/python -m scdfe_c --db /var/lib/scada/scada.sqlite3 --log-dir /var/log/scada

主进程按 fes_rtu_define.process_enable=1 选择 RTU；每个通道是一个独立通信线程。可用参数：--poll-interval 采集周期、--scan-interval 定义扫描周期、--retry-interval 重试周期、--retention-hours 日志保留小时数。

3.3 单 RTU 调试

python -m scdfe_c --db db/scada.sqlite3 --rtu-id 7 --max-cycles 10 --poll-interval 0.5
# 需要调试 YK/YT 时再增加
python -m scdfe_c --db db/scada.sqlite3 --rtu-id 7 --send-commands

调试入口只接受 --rtu-id，不接受 channel 参数。目标 RTU 的自动标志应为 0；同一个 RTU 同时只有一个通信所有者。

3.4 TCP 遥控/遥调指令服务

Web 的进程监控可启停 command-server。也可直接启动：

python -m scdfe_c.command_server --db db/scada.sqlite3 --host 127.0.0.1 --port 8890 --token change-me

服务接收一行一个 UTF-8 JSON 请求，写库事务提交后才返回成功：

{"request_id":"demo-1","op":"submit_command","token":"change-me","rtu_id":7,"kind":"yk","point_no":3,"value":1}
{"request_id":"demo-2","op":"submit_command","token":"change-me","rtu_id":7,"kind":"yt","point_no":4,"value":12.5}

kind 只允许 yk/yt，request_id 用于幂等；通信线程随后检测点表命令时间变化并通过已有规约主站下发。

3.5 Web 常用操作

  • 先新建 RTU，再配置唯一通道和对应协议参数/辅助表。
  • 在四遥标签维护点定义；删除 RTU 前页面会预览并级联删除通道、辅助表和四遥数据。
  • 在“进程监控”中按主进程 → 写库进程 → 通信线程顺序启动；停止时按通信线程 → 写库进程 → 主进程顺序停止。
  • 修改 process_enable 后主进程自动响应；点定义和协议参数变化会热重载。

四、scdfe_s：多通道协议测试

4.1 统一 Web 服务与独立页面

python -m scdfe_s.web.server --host 127.0.0.1 --port 8878 --db db/scada.sqlite3

打开 http://127.0.0.1:8878/。页面按职责分开：

页面用途
/channels通道及通道内四遥测点的新增、查询、修改、删除
/communication各协议通道通信状态、连接数、点数和即时操作
/processes每个协议服务进程的状态、启动/停止和日志入口
/logs运行日志按服务、类型、关键字和时段筛选查看
/iec104、/modbus-tcp、/modbus-rtu、/can、/opc-server、/bacnet-server协议专用联调页面

4.2 多通道与测点维护

“通道与测点”页面支持同时维护多个 RTU 通道；每条通道单独保存规约、参数和运行开关，并在选中通道后维护多个 YC/YX/YK/YT 测点。删除通道前确认，关联测点会同步删除。通道运行时先停止服务再修改监听、串口或协议参数。

4.3 单通道命令行

python -m scdfe_s.run_iec104_server --rtu-id 7 --bind-ip 127.0.0.1 --port 2404
python -m scdfe_s.run_modbus_tcp_server --rtu-id 3 --mode server --listen-port 1503 --max-cycles 1
python -m scdfe_s.run_modbus_rtu_server --rtu-id 4 --mode server --simulation --max-cycles 1
python -m scdfe_s.run_can_server --rtu-id 5 --mode server --simulation --max-cycles 1

四个入口都支持 --db、--schema-dir、--rtu-id；Modbus/CAN/RTU 入口还支持 --mode master|server、连接参数和 --poll-interval。--max-cycles 适合自动测试，正式服务不使用。

4.4 数据和安全

协议点映射从对应 RTU、通道和辅助表读取；主站类只在 client/ 导出，服务端类只在 server/ 导出。测试服务与 scdfe_c 的自动守护、写库进程相互独立。

五、scdfe_t：多通道四遥转发

5.1 独立页面

python -m scdfe_t.web.server --host 127.0.0.1 --port 8879 --db db/scada.sqlite3

打开 http://127.0.0.1:8879/communication.html；顶部可切换：

页面用途
/communication.html多转发通道、通道详情和通道内四遥测点映射
/processes.html每个转发通道独立进程的启停、PID、状态和心跳
/logs.html按通道筛选小时日志并查看正文

5.2 通道与测点 CRUD

通信监控页面支持新建、查询、编辑、删除多个转发通道；每个通道可独立启停。选中通道后，支持四遥映射测点的新增、查询、修改、删除和按类型筛选。一个通道可配置多个测点，多个通道可以同时运行。

对应 API：

GET/POST       /api/trans/channels
GET/PATCH/DELETE /api/trans/channels/{channel_id}
GET/POST       /api/trans/channels/{channel_id}/points
GET/PATCH/DELETE /api/trans/channels/{channel_id}/points/{kind}/{pnt_no}
POST            /api/trans/channels/{channel_id}/start|stop
GET             /api/trans/processes
GET             /api/trans/logs?channel_id={id}
GET             /api/trans/log?file={relative_log_path}

5.3 映射规则与命令行调试

每个映射填写 kind、source_rtu_id、source_pnt_no、转发 pnt_no，并按 IEC104 或 Modbus TCP 填写 IOA/寄存器字段。YC/YX 值来自 scdfe_c 表；远方 YK/YT 写回源 RTU 点表，scdfe_c 通信线程完成设备下发。

python -m scdfe_t --db db/scada.sqlite3 --channel-id 1 --max-cycles 10

转发定义约每秒检查一次，采集仍按通道扫描周期执行；修改映射后自动重载。监听地址、端口或规约变化时先停止通道再保存。

六、一个完整的配置流程

  1. 启动 scdfe_c.web.server，新建 RTU、通道、协议参数和四遥点。
  2. 将 RTU 的 process_enable 设为 1，启动 scdfe_c 主进程和写库进程，确认 YC/YX 有刷新时间和质量码。
  3. 需要现场协议联调时，启动 scdfe_s Web 或对应命令行入口，使用模拟服务端先验证报文、地址、字节序和命令回调。
  4. 启动 scdfe_t Web，新建 IEC104 或 Modbus TCP 转发通道，配置 YC/YX 上送和 YK/YT 下行映射。
  5. 在三个 Web 的进程监控中确认 PID、心跳、启动时间和日志；先停止通信进程，再改协议参数，保存后重新启动。
  6. 用远方客户端读 YC/YX、下发 YK/YT，核对源 RTU 点表的值、质量和命令处理时间。
建议所有模块先使用 loopback 或模拟模式验证；串口、真实 CAN 总线、现场 IEC104 主站和 OPC/BACnet 设备属于现场联调范围。

八、进程监控和日志

三套模块均使用独立进程日志；日志按 logs/YYYY/MM/DD/HH/ 分目录，每小时一个文件，日志正文时间只显示 HH:MM:SS，类型为“日志、警告、错误、进程”。页面支持按关键字、启止时间、类型和 RTU/通道过滤。

进程日志标识示例状态重点
scdfe_c 主进程scdfe_c-main-YYYYMMDD-HH.log守护扫描、线程拉起、整体错误
写库进程scdfe_c-db-writer-YYYYMMDD-HH.log批量提交、队列、事务错误
通信线程scdfe_c-rtu-{id}-...连接、采集、命令下发、热重载
scdfe_t 转发进程scdfe_t-channel-{id}-...映射、远方连接、命令回写

三个模块都把进程监控、通信监控和运行日志拆成独立页面。Web 进程监控显示 PID、状态、启动/停止时间、心跳、退出码和错误；日志查看器显示文件内容，不需要登录服务器手工打开文件。

九、常见问题

端口已被占用

确认没有重复启动同一 Web 或协议服务；更换 --port/--listen-port，并在页面保存对应配置。

RTU 没有自动通信

检查 RTU 是否有有效通道、channel_type 是否为已支持规约、process_enable=1，再查看 scdfe_c 主进程和 RTU 日志。

遥控/遥调已写库但设备无动作

核对点表命令时间是否大于处理时间、协议辅助表地址/类型/写功能码是否正确，以及通信线程是否在线。TCP 指令服务只负责认证和写库，实际下发由 scdfe_c 通信线程完成。

修改定义没有立即生效

scdfe_c 在定义扫描周期应用变化；scdfe_t 约每秒检查转发定义。修改监听地址、端口或协议时先停止对应进程再保存。

跨平台运行

使用项目虚拟环境中的 Python 和模块入口；Windows、Linux 都不要依赖固定盘符。日志、数据库和 schema 目录通过命令行显式传入即可。

文档对应当前目录结构和接口：client/ 放主站/客户端类，server/ 放服务端/从站类；旧的 api/web 顶层兼容入口不再使用。建议随版本提交同步更新本文。
