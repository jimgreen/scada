Modbus 常用功能验证
与 C/S/T 数据库解耦

常用 TCP/RTU 软件功能及 C/T 数据库交换验证通过。T 只提供 IEC104 与 Modbus TCP 转发；S 保留独立模拟库，C/T 共用业务库。

本轮实现：T 已取消对 C 写库 IPC 的依赖；命令直接提交数据库事务，C 独立读取与执行。Modbus 15/16 多点命令统一校验、整批提交或回滚。

独立收发，数据库交换

现场设备 ⇄ C 采集 ⇄ scada.sqlite3 ⇄ T 转发 ⇄ 远方系统
S 模拟器 ⇄ 独立 scdfe_s.sqlite3

C/T 通过四遥表交换状态与待处理命令，各自拥有连接、报文解析、超时及重连逻辑。T 不把报文或运行时对象交给 C，也不再访问 C 的命令 IPC。S 使用自己的配置和模拟数据，独立收发协议报文。

回环验收中，S 充当外部设备模拟端供 C 连接，以验证两端协议兼容；这条测试接线不构成生产组件间的内部调用依赖。测试只使用临时数据库与 127.0.0.1 随机端口。

T 写入 value、cmd_time 与待处理状态；C 发现后独立下发，更新 cmd_handle_time 及处理状态。C 停止时命令保存在数据库，不能据 T 的肯定应答宣称设备已执行。S 数据库路径保持不变，未合并到 C/T 业务库。

查询接口的 confirmation_scope / command_confirmation_scope 现在为 database_commit；device_execution_confirmed 仍为 null。Modbus 能力接口声明批量请求数据库写入原子性以及无需 C 进程在线。

新增解耦测试实际启动 T 的 TCP/IEC104 服务，同时禁止构造 C 的 IPC 客户端，验证无 C 进程时仍可提交。多点请求的后一个点闭锁或越限时，前一个点的值、命令时刻及线上值均保持原状；两个并发提交者不能覆盖同点待处理命令。

初轮测试曾在 S 已收命令、C 回执尚未提交时立即发送下一条同点命令，观察到异常码 04。其原因是命令槽仍待处理。本轮分别测量两个时刻，成功连续指令在上一条 C 回执完成后发出，未取消防覆盖校验。

TCP 每通道 64 遥测 + 64 遥信，RTU 字节流为 8 + 8 点；另含遥控/遥调命令点。S 数据库扫描、C 轮询、T 刷新均设 50 ms；C 批量写库等待间隔 100 ms、阈值 500 条；通信响应超时 500 ms。

状态时延从 S 数据库提交完成开始，至 C 写库或下游主站主动读到所有新值结束，观察间隔 5 ms。四区轮询测试在运行中的 C 主站上增加采集调用，包含连接锁等待；4 通道结果只测其中一个主站的每次调用。命令时延分别测 S 值更新和 C 回执落库。

TCP 两种负载各 12 批，RTU 6 批；四区采集各 30 次；命令为 4 / 16 / 4 次。小样本使用 nearest-rank P95，与最大值可能相同。4 通道触发 500 条批量阈值的机会更多，不能据此推断线性扩展或吞吐上限。

正常运行阶段 C 错误计数为 0；TCP 主动停止 S 后，对应 C 通道记录一次预期通信失败并成功重连。RTU 数值仅代表 socket:// 回环及软件栈开销，不代表 19200 波特的物理串口性能。

实际项目需要在 call/data 映射中定义连续读取范围；跨地址空洞、不同功能码或不同站号不能直接套用此收益。运行时使用已配置的采集计划，本轮未把所有离散请求自动合并。

范围与尚未验证部分

RTU 已验证真实帧和 CRC，尚未连接物理串口。 S 使用生产 ModbusRtuServerService 的非内存模拟模式，C 使用 ModbusRtuMaster；socket:// 提供回环字节传输，RTU ADU 不含 MBAP。配置使用 19200、8E1，但波特率、校验位电气行为、总线静默间隔、RS485 仲裁及线路干扰未实测。

S/C/T 验收运行循环为线程，C 内部批量写库为独立进程；未测完整监督器及每个 T 通道独立 OS 进程时的 CPU/内存曲线。测试批数有限，未进行长时间稳定性、链路抖动、网络丢包及极限并发认证。

Modbus 基础寄存器模型不承载 IEC104 的质量位、COT 或时间标签。S 的状态字段变化不会自动变为协议质量标志，读取值也不能证明历史变化逐条留存。需要质量或时间透传时应明确另行配置寄存器映射。

批量命令原子性限于数据库受理；多个现场设备动作不构成分布式事务。写响应丢失不能证明设备未执行，控制命令不应盲目重发。单点仍只有一个待处理槽；批量请求若重复指向同一源点，会整批拒绝。
