规约接口修复与使用说明

范围：C/S 的 IEC104、Modbus TCP/RTU 和 CAN；T 仅 IEC104 与 Modbus TCP 转发。本文件记录已落地的接口和验证边界，不代表已完成全部规约符合性认证。

修复内容 · 接口用法 · 尚存限制 · 验证证据

已落地修改

IEC104 撤销T 对 DEACTIVATION 单独处理，不再重复提交执行；新增遥调 cancel_yt_point。撤销不回滚已提交命令。
IEC104 质量状态S 同时比较值和质量状态，质量单独变化及恢复也会主动上送，不依赖人机页面调用。
CP56 命令修正 45→58、46→59、48→61、49→62、50→63 映射；发送和撤销均保留配置时标及限定词。
IEC104 测试接口test_command() 发送应用测试命令；原 test_fr() 明确拒绝主动 U 帧请求，U TESTFR 由原生驱动 t3 定时器管理。
S 命令行入口run_iec104_server.py 复用 Web 服务的独立数据库同步与命令接收落库逻辑；退出关闭服务和数据库。
S Modbus 工程值有点映射时从数据库加载地址、功能码和编码，支持 16/32 位整数、浮点和四种 32 位字序。TCP 与真实 RTU 入口共用编码器。
S Modbus 自主同步每 50ms 检查数据库 data_version，有提交变化时扫描 YC/YX；浮点不再被写库接口截断成整数。保持寄存器/线圈可由对端写入并同步数据库。
CAN 报文定义C 与 S 接入 fes_channel_can_frame_define，支持周期次数、手动发送和按 sequence_no 排序的数据库回放组。每总线一个调度线程，停止服务时清空队列。
配置与查询接口C/S/T 新增 GET /api/protocol-capabilities；CP24 配置明确拒绝，CAN 非法帧启动前校验，故障注入和外部回放文件不再被误当作可执行调度。
Web 表单C 补全受支持的 IEC 类型；T 增加 k/w/t1/t2/t3、时标、ASDU 诊断阈值和 Modbus 地址基准，并注明命令确认表示写库受理。

接口用法

三个 Web 服务均提供能力查询。实际服务地址、通道与 RTU 仍以本机配置为准。

GET /api/protocol-capabilities

# S 通信测试页：严格控制所选 RTU，不调用默认规约服务
POST /api/rtus/{rtu_id}/service/start  # 请求体 {}
POST /api/rtus/{rtu_id}/service/stop   # 请求体 {}
POST /api/rtus/{rtu_id}/service/poll   # Modbus/CAN 等支持采集的规约

# IEC104 Python 客户端
master.send_yk_point(1, True)  # 按点定义选择 DIRECT 或 SELECT_AND_EXECUTE
master.send_yt_point(1, 12.5)
master.cancel_yk_point(1, True)
master.cancel_yt_point(1, 12.5)
master.test_command(with_time=True)

# S 的 CAN / CAN 服务端：从已启用的数据库定义发送
POST /api/can/schedule
{"frame_id": 12}

POST /api/can-server/schedule
{"replay_group": "验收回放"}

CAN 的 frame_id 是报文定义表主键 id，不是仲裁 ID；只触发 manual 模式。回放只选 replay 模式且分组匹配的记录，按序号及 id 排序。periodic 模式随服务启动，repeat_count=0 表示持续发送；手动与回放的 0 表示发送一次。period_ms 表示相邻调度间隔，单位毫秒。

S 的 Modbus 工程值来自四遥表，地址和编码来自既有 call/data/ytyk 映射表。先配置通道与 RTU，再定义点及映射；使用同一站号。地址基准只转换一次。四字节字序 0/1/2/3 分别对应 DCBA/BADC/CDAB/ABCD。编辑数据库后，S 自主刷新运行点值。

寄存器切片、取反与特殊遥控

数据映射 trans_type=6 为无符号字节：twobytedata_byteseq=0 取低字节，非零取高字节；类型 7 为高字节有符号 int8。类型 8/9 使用 offset_bit 和 all_bit 定义位段，按 twobytedata_byteseq 解释寄存器字节序；类型 8 可用 if_reverse 取反。不同点可共用同一寄存器的互不重叠位段，修改一段会保留其他位。

遥控 ifreverse 适用于线圈和寄存器。05/15 使用线圈；06/16 支持 ytyk_type=1/2 的 FF00/0000、类型 6 的指定位或 FF/00、类型 7 的特殊位读改写。special_yk_bit 从 0 起；类型 7 的 current_value 为编码前、已按配置字节序还原的 16 位当前值，跨设备读改写不具备原子性。特殊位不能借用 05 功能码发送私有编码。

一个 Modbus 写请求涉及的所有映射点在同一个数据库事务中提交，失败整批回滚并返回异常码 04；非法编码返回 03。相应实时值、刷新时间及命令处理时间随提交更新。数据库自主扫描遇到更新的远端写入，会丢弃旧扫描并重新读取。查看本轮验证与性能结果。

没有新增业务表，也没有修改现场数据库；原有数据库运行态及用户已删除的旧文档均保留。

尚存能力限制

CP24Time2ac104 2.2.1+scada.1 / scada.2 / scada.3 均不支持。数据库保存和运行时注册返回明确错误；需要原生协议库扩展，未静默转换为 CP56。
独立选择阶段支持直接执行、自动选择并执行和撤销；当前驱动未开放“仅选择、稍后单独执行”的接口。
ASDU 长度通用快照接口中的 max_asdu_length 是诊断阈值，原生上限为 249；新 SOE 专用组帧接口遵守配置长度限制。
T 命令确认IEC104/Modbus 应答表示命令已提交共享数据库，不能证明现场设备动作完成；API 返回 confirmation_scope=database_commit，device_execution_confirmed=null。C 自主读取并执行待处理命令。
S Modbus 映射边界已补齐寄存器位/字节切片、取反和 06/16 寄存器遥控。同址不同点的位掩码须互不重叠，重叠别名仍拒绝启动；特殊位遥控的读改写当前值需由调用方保证新鲜。无映射时保留原始寄存器模拟模式，RTU simulation 仍是内存模拟器。本轮补齐与性能验证。
CAN 高层与硬件DBC 文件解析、CANopen/J1939/UDS 完整协议栈尚未实现。扩展表字段不等于运行能力。ACK/CRC/位填充错误注入、Bus-off 实测、波形与环境试验仍需专用硬件；本轮仅使用 virtual 总线。
CAN 调度边界period_ms 使用报文定义表；点映射中的 period_ms/DBC 名称不构成独立调度或 DBC 导入。replay_source 外部文件导入未实现，周期发送不提供硬实时保证。

第三轮效率与交互更新

C 表格、S 四遥页和 T 通道选择列表会合并同一范围的重叠读取；保存后仍会再次读取最新结果，切换 RTU 或通道时旧响应不能覆盖新范围。C 的“常用/实时/全部字段”切换会按视图重新查询；S 四遥页内容不变时保留已有表格行。

共用数据库接口减少字段处理和逐点 SQL 调用，T 批量写入转发状态，CAN 密集信号共享报文整数转换。Modbus 多位数据的 offset_bit 与 all_bit 之和不得超过 16。查看本轮性能对比、验证与边界。

第四轮效率与交互更新

S 的 IEC104 数据库同步按信息体类型批量上送变化值和质量；发送失败保留待重发标记，避免内存值已经改变而漏发。原生驱动负责 ASDU 拆分，50ms 数据库检查间隔保持不变。共用批量更新接口按表和主键分块返回记录，保持事务原子性与最终版本。

C/S 数据变化时局部更新单元格并保留按钮焦点；S 编辑、删除使用最新值和版本；T 不再重复重建相同表头。查看性能对比、真实 TCP 回环和浏览器验证。

第五轮效率与交互更新

T 的 IEC104 变化上送改为按类型批量发送，隔离无效点和失败类型组，成功点更新转发状态，失败点重试；批量新增映射通过分组写入和分块回读减少多 RTU 维护开销。源目录接口增加可选 include_rtus=0，供已加载目录的页面仅查询当前 RTU 源点，默认响应保持兼容。

C 合并重叠 RTU 目录读取，C/S 保留未变化的下拉选项。T 源点编辑抑制过期响应和错误，加载期间禁用旧源点，批量保存使用当前所选 RTU。查看本轮性能对比与验证。

C/S/T 数据库解耦 · 2026-11-13

C/T 共享 scada.sqlite3 业务库；S 保留独立的 scdfe_s.sqlite3 模拟库。各进程独立处理规约报文，T 直接在数据库事务中提交命令，C 自主读取待处理命令并下发，不再通过 C 写库 IPC 提交。C 未启动时 T 仍能保存命令。

Modbus 15/16 涉及的源点在一个事务中统一校验与提交，闭锁、待处理指令、越限等失败会整批回滚。协议确认表示数据库提交完成；查询接口的 confirmation_scope / command_confirmation_scope 改为 database_commit，device_execution_confirmed 仍为 null。设备执行结果由 C 的状态和 cmd_handle_time 表示。
