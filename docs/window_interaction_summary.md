## 1. 总体目标

本窗口围绕一个跨 Windows/Linux 的多协议 SCADA 系统持续迭代，目标是：

- 覆盖 IEC104、Modbus TCP、Modbus RTU、CAN、BACnet、OPC 等通信规约。
- 将客户端/从站、服务端/主站、自动通信守护、四遥转发和 Web 运维功能分层组织。
- 支持 RTU、通道、协议辅助参数以及遥测、遥信、遥控、遥调点表的维护。
- 支持通信运行状态、进程状态、日志和控制指令的 Web 化管理。
- 在不保留旧接口和旧名称别名的前提下，持续优化通信、数据库和人机界面效率。

## 2. 目录与模块边界

窗口中多次调整了目录职责，最终形成以下约定：

- `client/`：定义从站/客户端类的 Python 文件，包括 `iec104.py`、`modbus_tcp.py`、`modbus_rtu.py`、`can.py`、`bacnet.py`、`opc.py`。
- `server/`：定义主站/服务端类的 Python 文件，包括 `iec104_server.py`、`modbus_tcp_server.py`、`modbus_rtu_server.py`、`can_server.py`、`bacnet_server.py`、`opc_server.py` 等。
- `scdfe_c/`：自动通信守护、通信线程、写库进程、TCP 指令服务及其 Web 管理。
- `scdfe_s/`：服务端/主站通道运行入口和统一 Web 管理。
- `scdfe_t/`：四遥转发功能，原目录 `scdfe_f` 改为 `scdfe_t`，`forward` 相关名称改为 `trans`。
- 旧的顶层 `api/`、旧入口和旧名称别名按“不考虑向下兼容”的要求清理，不作为公开访问入口。

通信适配器优先使用成熟第三方模块，例如 `c104`、`pyModbusTCP`、`pymodbus` 和 `python-can`，协议状态机与报文处理不再重复建设自研基础模块。

## 3. 数据库与点表模型

数据库经历了字段清理、协议辅助表补充、索引优化和测试数据扩充：

- RTU 定义、通道定义、协议参数表、协议点映射表和四遥点表同步维护。
- 每个测试站配置 100 个遥测、100 个遥信、20 个遥控、20 个遥调点。
- 测点原始值、工程值和质量码按点独立生成，避免所有测点出现相同数据。
- 覆盖 IEC104、Modbus TCP、Modbus RTU、CAN、BACnet、OPC 的辅助定义和点映射。
- RTU 删除时，对应通道、辅助参数和四遥点表执行关联删除，并在 Web 操作前给出确认提示。
- 已按用户要求删除设备值等冗余字段；保留原始值和工程值。
- `process_restart` 相关记录最终按要求删除；主进程运行详情不再保留该组重启字段。
- 通信和写库模块根据当前 schema 读写，避免依赖旧字段名或旧别名。

测试数据脚本采用稳定业务编码和事务写入，重复运行保持幂等；重复执行可返回 `added=0`，不重复生成参数或测点。

## 4. `scdfe_c` 自动通信与指令链路

`scdfe_c` 的职责从早期“每通道一个进程”逐步调整为主进程管理多个通信线程：

- 主进程遍历 RTU 表，按配置启动通信线程；线程异常被隔离和记录，避免单个通道影响其他通道。
- 启动通信线程时增加顺序延迟，降低多通道同时启动造成的系统拥塞。
- RTU 标志位控制是否参加自动通信和守护；未参加自动通信的 RTU 仍可单独启动调试任务。
- 单独调试入口只接受 `rtu-id`，同一 RTU 同时只允许一个调试任务；自动守护任务在同一服务器中只能启动一次。
- 写库改为独立写进程：通信线程把更新内容通过 IPC 发送给写库进程，由写库进程按批次统一更新数据库。
- 写库队列空闲周期从 200 ms 降至 100 ms，并围绕批量大小做过 100、200、500、1000、2000、5000 点对比。
- 增加 TCP command-server，默认监听 `127.0.0.1:8890`，使用换行 JSON 协议，支持 token、`request_id` 幂等检查和事务提交后的 ACK。
- command-server 接收遥控/遥调请求，写入数据库后调用现有通信线程和协议主站完成实际下发。
- 主进程、写库进程、通信线程、调试任务和 TCP 指令服务均纳入进程监控、启停控制和日志体系。

日志按进程独立保存，每小时一个文件，目录按年/月/日/时分层；文件名只体现 RTU 号，正文只显示时分秒，日志类型显示为“日志、警告、错误、进程”。

## 5. `scdfe_s` 服务端/主站功能

`scdfe_s` 提供协议服务入口和统一 Web 管理：

- 已有 IEC104、Modbus TCP、Modbus RTU、CAN 服务/主站运行入口，入口名称统一为 `run_*_server.py`。
- 支持多个 RTU/通道，每个通道维护多个 YC、YX、YK、YT 测点。
- 通道支持查询、新建、修改、删除；通道内测点支持查询、新建、修改、删除。
- 主要接口：
  - `/api/channels`
  - `/api/channels/{rtu_id}`
  - `/api/channels/{rtu_id}/points/{yc|yx|yk|yt}`
  - `/api/channels/{rtu_id}/points/{kind}/{pnt_no}`
- Web 页面分为进程监控、通信监控、运行日志等独立页面，并提供通道和测点维护页面。
- 协议服务状态查询使用四表 `COUNT(*)` 聚合，避免每次状态刷新都物化完整点表。

当前实现模型是“多个 RTU，每个 RTU 一个通道”。因此已经支持多 RTU 通道和每通道多测点；如果业务继续要求“同一个 RTU 下配置多个相互独立的通道”，需要另建独立通道配置表、通道点映射表和通道服务实例模型，不能只扩展现有一 RTU 一通道字段。

## 6. `scdfe_t` 四遥转发功能

`scdfe_t` 是独立的四遥转发模块，原 `scdfe_f` 和 `forward` 命名已按要求迁移：

- 支持多个独立转发通道；每个转发通道可以独立定义拟转发的 YC、YX、YK、YT 点。
- 支持 IEC104 和 Modbus TCP 转发。
- YC/YX 从 `scdfe_c` 数据库读取并转发；远方 YK/YT 指令写回 `scdfe_c` 数据库，再由 `scdfe_c` 完成实际下发。
- 每个转发通道支持独立进程、状态、日志和启停控制。
- Web API 覆盖转发通道和测点的增删改查、进程查询、日志查询和通道启停。
- 定义加载增加缓存和低频变化检查：采集周期保持不变，定义大约每 1 秒刷新一次，减少重复数据库查询和 JSON 签名计算。

## 7. Web 人机界面调整

窗口内对 Web 页面进行了多轮重构和精简：

- RTU、通道、遥测、遥信、遥调、遥控及协议辅助表整合到统一页面，使用分页标签切换。
- RTU 选择控件移到分页标签上方，一次选择后对各页生效。
- 主进程、写库进程、通信进程/线程和调试任务分别展示，可独立启停，并支持按顺序一键启停总功能。
- 运行日志独立成页，支持关键字、起止时段和日志类型过滤，并能查看具体正文。
- 日志目录在页面上按年、月、日、小时分级显示，而不是把所有文件堆在一个列表中。
- 日志类型采用固定中文名称并统一宽度；正文时间只显示时分秒，不含日期和时区。
- 心跳时间仅显示 24 小时制时分秒；启动、停止和四遥采集时间显示“年-月-日 时:分:秒”。
- 页面去除冗余说明文字、重启操作显示和旧字段；布局收窄，减少超宽和信息分散问题。
- 使用者可以通过 Web 页面下发遥控和遥调指令。

主要页面包括：

- `scdfe_s`：`/`、`/channels`、`/communication`、`/processes`、`/logs`、`/api-docs`
- `scdfe_t`：`/`、`/communication.html`、`/processes.html`、`/logs.html`
- `scdfe_c`：主控制、进程监控、通信监控、日志和指令服务页面

## 8. 性能优化方向与已验证结果

窗口中持续围绕通信、数据库和人机交互模块寻找耗时热点：

- `scdfe_t` 定义加载由每个扫描周期完整查询改为约每秒检查一次；在 1200 个周期的 stub 测试中，`load()` 次数从约 1201 次降到约 19 次，减少约 98.4%。
- `scdfe_s` 通道状态从物化四张完整点表改为 `COUNT(*)` 聚合；2400 点状态查询从约 0.0298 秒降至约 0.0016 秒，约 18.6 倍提升。
- 写库采用批量事务和独立进程，避免通信线程逐点写 SQLite。
- 协议定义、点表快照和测点映射增加缓存，降低重复解析和对象分配。
- 对 IEC104、Modbus TCP、Modbus RTU 和 CAN 分别做过通信热点、轮询、解码和快照相关分析；优化以保持功能和协议时序为前提。

## 9. 验证结果

已完成的专项验证包括：

- `scdfe_c` TCP command-server：9/9。
- `scdfe_c` writer IPC：4/4。
- `scdfe_c` 进程监控：7/7；控制流程：30/30；Web 全量接口：32/32。
- `scdfe_s` Web UI：3/3；Web 监控：2/2；通道和 YC/YX/YK/YT CRUD 通过。
- `scdfe_t` 协议服务、schema、快照、点映射、投影及 IEC104/Modbus TCP 回环专项通过。
- 页面和健康接口已验证可用：`8877`、`8878`、`8879` 对应服务均可返回 HTTP 200。
- 本地 IEC104 回环覆盖总召唤、遥信/遥测自发上送、遥控、遥调、时钟同步和关闭清理；该验证不等同于现场设备验证。

完整回归曾出现 1 个失败和 1 个错误，集中在两个 IEC104 异步测试；随后分别隔离重复 5 次均通过，判断为 `c104` 异步时序竞态，未据此修改协议业务逻辑。测试中出现的写库进程异常日志属于故意验证监督器重建的测试场景。
