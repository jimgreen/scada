通信、数据库与页面刷新效率验证

本轮集中处理 IEC104 多点变化上送、批量更新返回记录和 C/S/T 表格局部刷新。T 转发范围仍为 IEC104 与 Modbus TCP。

数据库为同一临时 SQLite 文件及相同连接池配置，交替执行前后版本，各 21 次采样取中位数。2000 点返回记录的 SELECT 从 2000 次降至 5 次，两侧都仅提交一次事务。不返回记录的路径作为对照，未改变其实现。

IEC104 使用真实 c104/lib60870 与本机 TCP 回环，每次 80 遥测 + 80 遥信，其中各半使用 CP56 时间标签；每个版本 6 次，轮换先后顺序。发送提交耗时包括扫描、值转换、质量处理和 native 发送调用；完整接收耗时包含本机驱动调度与 TCP 传输。APDU 数据量仅计算 COT=3 的 I 帧，不包含 TCP/IP 头与链路确认帧。

实现及正确性

  • S 数据库同步保持 50ms 检查间隔，将变化监视点按 native 信息体类型分组上送；底层按 ASDU 大小拆帧，值和质量同时更新，支持质量单独变化及 CP56 时间标签。
  • 发送失败时保留待重发点，避免 native 内存已变而下一轮漏发。成功指底层发送接口接收批次，并非对端业务处理确认；若后续类型组失败，重试可能重复之前已接收的状态快照。
  • 批量更新返回记录按表和主键分块查询，遵守 SQLite 参数上限，保留输入顺序、重复主键的最终版本、独立响应对象及整批回滚。此共用接口也用于 S 的 Modbus/CAN 批量写入返回值。
  • C/S 值变化时更新必要单元格，保留表格行和按钮焦点；S 编辑与删除按钮同步最新数据和版本。T 保留不变表头。

验证结果

整套回归首次为 577 通过、1 跳过、450 子测试通过，另 1 项在线程重载测试清理临时数据库时发生 WinError 32。已修正该测试，等待协作停止接口返回成功后再清理；随后相关 41 项测试及 27 子测试全部通过（包括新增单主键用例）。合计覆盖 579 个通过的独立测试，1 项 Windows 符号链接权限跳过；未宣称修复后重跑了整套套件。

真实 Chromium：新增局部刷新检查 13 项、原有页面回归 62 项、上一轮请求合并与陈旧响应检查 19 项，共 94 项通过。

覆盖多 RTU、多表、复合与单字段主键、低 SQLite 参数上限、重复键、触发器删除导致回滚；IEC104 混合类型、时间标签、质量、拆帧、总召唤及失败重发。旧规约和前端回归继续执行。

适用边界

这是本机临时数据库和 TCP 回环结果，不能代替现场多通道吞吐量、CAN 硬件总线、串口与长期稳定性验收。本轮没有修改 Modbus/CAN 编解码器，因此不主张这两类协议线速提高。IEC104 CP24、独立选择阶段及 CAN 高层协议栈等原有边界仍见接口使用说明。轮询数据库得到的是已提交状态快照，不是每次中间变化的 SOE 日志。
