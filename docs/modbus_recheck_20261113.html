解耦方式与测试方法

C/T 共用 scada.sqlite3，通过数据库交换点值与待处理命令；S 保留独立 scdfe_s.sqlite3。各自负责报文与连接，T 不依赖 C 的 IPC 服务。

验收时 S 作为外部设备模拟端与 C 建立协议回环。数据路径为：S 独立库 → S 协议服务 → C 采集 → C/T 共享库 → T 协议服务 → 下游主站。此接线用于测试协议兼容，不引入生产内部报文转交。

T 肯定写响应只确认数据库已提交；C 随后读取、下发并写回处理状态。cmd_time 与 cmd_handle_time 区分受理和处理完成；同点已有待处理命令时拒绝覆盖。批量原子性只涵盖数据库受理，不代表多个设备动作构成事务。

全部测试使用临时数据库及本机随机端口；未变更业务数据库、生产服务或业务代码。本次新增报告与复验记录，保留此前未提交的解耦修改及其他工作区变更。

验证边界

RTU 使用生产串口适配器及真实 RTU 帧、CRC，通过 socket:// 承载字节流。配置 19200、8E1，但未连接实体串口或 RS485 设备；测量不能作为物理波特率、帧间静默、总线冲突或抗干扰结果。

1/4/8 通道分别执行 30/30/60 批更新，RTU 6 批；不是长时间稳定性试验。测试使用运行时线程和独立 C 批量写库进程，未测完整生产监督器部署的 CPU/内存曲线，也未覆盖网络抖动、断电恢复或极限并发。

Modbus 寄存器值不自带 IEC104 质量位、COT 或时间标签；需要透传时应配置相应寄存器。此次验证点值及命令处理，不能证明每次瞬时变化均按事件留存。RTU 的实际端口拔插恢复仍需硬件验收。
