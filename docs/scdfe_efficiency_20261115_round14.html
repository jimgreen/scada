本轮落地

批量遥控、遥调改为按 RTU 与点类型分组读取，400 点一块限制 SQL 参数数，RTU 类型每批分块查询。全部点在同一写事务内完成校验，随后分类型执行更新，并再次读取完整回执以保留触发器更新字段和输入顺序。末点越限、闭锁、非法地址或待处理槽位冲突仍导致整批回滚；FULL 持久化不变。

新增 T 指令入库分段诊断：连接获取、参数设置、写锁、读取校验、更新及回执、FULL 提交、参数恢复、总耗时。保存最近 256 个阶段样本的分位数，以及每服务最近 16 次超过 100 ms 或失败请求；关联前 8 个 RTU/点/命令时标，不记录命令值。沿用运行诊断 JSON 快照持久化，无需新建业务表。诊断异常不能把已提交命令变成失败。

运行诊断页显示累计请求数、未提交数、失败阶段及慢请求关联。相同慢批次、指令表和配置检查内容不再重复替换 DOM；隐藏页暂停、请求防重叠和失败保留上次结果仍保留。人工结案接口收到错误类型的阶段字段时返回参数错误。

相同代码和 500 ms 门槛的第二次 TCP 1/4 通道及 RTU socket:// 完整验收通过；首次失败保留在原始数据中。报文验证工具现在无论成功失败都保存观测报文与命令分段快照，便于后续对齐。超时不等于设备未执行，不自动重发旧指令，也未通过增大超时隐藏问题。

IEC104 回归中也捕获到一个不同的慢请求：T 通道 4 入库总计约 263.379 ms，其中 FULL 提交约 262.166 ms、写锁约 0.017 ms。此记录表明该次耗时集中在提交阶段，不能当成锁竞争；提交可能涉及文件同步或检查点，当前证据仍不足以进一步判定。正常指令持久化等级未降低。

运行诊断中的“已提交”仅指数据库已经接受指令，不代表设备执行或客户端已收到响应。该诊断测量从 DatabaseCommandWriter 调用到释放连接，未覆盖协议解析、之前的请求排队、日志与网络发送。慢写库批次和慢指令请求为两种独立观察，不能直接相加。
