# SCADA 数据库结构与升级

四遥业务表仍分别保存遥测、遥信、遥控和遥调。每张表以 `(rtu_id, pnt_no)` 为物理主键，SQLite 直接按这个键组织记录，不再额外存一份行号索引。查询、外键和乐观锁 `_version` 不变；直接编写 SQL 的工具应使用业务主键，不应读取四遥表的隐式 `rowid`。

每个 RTU 现在只有一行内部版本记录：`_scada_rtu_version(rtu_id, definition_version, command_version)`。修改静态定义和下发命令分别推进自己的计数；点值、心跳和命令回执沿用原有触发条件。计数不参与操作员的行版本控制。

转发点只维护一个 `kind`。转发 Web/API 创建点映射时，填写转发类型、转发点号和源 RTU 即可；源点号不同时再填写。转发专用 API 仍会在响应中派生 `source_kind`，旧客户端提交相同值也可以，冲突值会被拒绝。直接使用 SQLite 或通用表接口时，删除请求里的 `source_kind`，用 `kind` 检索和写入。新建转发通道及需要合成 ID 的 IEC104、BACnet、OPC 参数记录时，通道维护接口由 SQLite 分配编号。

升级现有数据库时，在项目根目录使用项目解释器：

1. `python -m tools.simplify_schema --db <数据库路径>` 只读列出拟执行的变更。
2. 记录正在运行的通道，停止该数据库的 Web 和写入进程，再执行 `python -m tools.simplify_schema --db <数据库路径> --apply --compact`。工具在数据库旁的 `backups` 目录创建并校验完整备份，再在单个事务中迁移。未识别的指纹、原来不一致的映射、影响迁移的外部依赖或完整性错误都会中止操作。重复运行不再改表或建立备份。
3. `--compact` 是可选项，迁移成功后单独执行 `VACUUM` 归还空闲页；压缩失败不会撤销已经提交的迁移。预留备份及迁移过程所需的磁盘空间。
4. 启动新版 Web，按升级前的运行状态恢复通道。不要将旧进程连接到新结构。需要回退时，先停止所有访问者，保留当前库及 WAL 文件，在单独路径从完整备份恢复，配套使用升级前的程序再启动。
