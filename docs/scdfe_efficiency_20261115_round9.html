已实现并应用

  • C：用最老待写消息的年龄限制批量等待，防止连续小包把提交不断推迟；保留 FIFO 排空、停止、锁冲突回退及确认语义。
  • S：首次同步全量读取，之后按 RTU/点号读取提交后的值或质量变化。辅助索引与原更新同事务，支持回滚、删除、重建及独立游标；只有发布成功才推进游标。
  • S/T：连接详情按 after 游标追加，突发超过一页时连续补读；保留页面节点，最多 2000 条。浏览历史冻结自动刷新，筛选切换丢弃旧请求结果。
  • 使用说明 HTML 已同步；C/T 共享业务库、S 独立数据库，程序间数据交互方式保持原约定。

新增内部表 _scada_monitor_change 每个历史点键保留一个最新标记，包含删除标记。它不替代逐条 SOE 事件表；长期反复新增/删除点号会增加其键数。数据库严格校验和结构检查工具已识别该辅助表。

正确性验证

167 项测试与 286 项子测试通过；浏览器交互检查 15 项通过。Python 编译、JavaScript 语法和 Git 差异空白检查通过。

  • IEC104：总召确认/数据/结束、值和质量变化、CA/IOA 与 RTU 隔离、直接执行、选择执行、撤销、周期上送及断线重连；故障注入前各通道错误数为 0。
  • SOE：CP56 时标与原始双点状态、逐事件持久化、同点连续变位、发送失败/断线游标恢复；最新值索引合并 3 次变化时，SOE 仍保留 3 条事件。
  • Modbus：真实 TCP 1/4 通道和 RTU 帧经 socket 字节链路，覆盖 01/02/03/04/05/06/15/16、地址基准、异常响应、读回及独立数据库更新。RTU 字节链路不等于真实串口电气测试。
  • CAN：既有编码、轮询、调度和虚拟总线回归通过；没有进行物理总线、温度、电磁干扰或硬件错误注入验收。
  • Web：250 条突发分批补齐、超过 2000 条时滚动保留、历史分页、筛选竞态、异常重试、节点保留与内容转义。

应用与现场配置检查

一致性备份已经 quick_check 校验。C 主进程/写库/指令进程正常停止并以新 PID 恢复；三端 Web 健康接口返回 200；S 原活动 13 个服务恢复。T 原先未运行，本轮没有启动原本停止的通道。

  • RTU 3：127.0.0.1:1502 无监听，S Modbus TCP 服务未运行。
  • RTU 4：S 使用本地模拟模式，C 的 loop:// 不构成 C/S 配对串口通信。
  • RTU 6：S BACnet 处于本地模拟模式；C 指向 47808，当前只有 C 在 UDP 47809 监听。
  • RTU 7：127.0.0.1:4840 无监听，S OPC UA 服务未运行。
  • T：通道 1 和 3 都配置 0.0.0.0:2404，与当前 S 的 127.0.0.1:2404 也冲突。历史进程记录为退出码 0，现有检查不能反推具体停止操作来源。

这些配置保留原值；应按真实测试拓扑分配唯一监听端口、选择实际服务/串口模式，再启动需要的通道。修改端口时需要同步对应客户端目标地址。
