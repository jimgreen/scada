遥控/遥调通过每通道各验证 DIRECT 与 SELECT_AND_EXECUTE；检查下游发送一次执行或“选择+执行”两帧，以及 S 数据库最终值。撤销未重复执行，S 的 cmd_handle_time 不再变化。
周期上送通过已有连接修改报告周期后，收到 COT=1 且监视对象完整；已有回归另验证通过数据库编辑周期后不重建连接。
重连与恢复通过停止私有 S 服务、改变数据库、重启，C 自动重连并发起总召，T 收到新值；下游新连接也能总召取回最新值及质量。
帧与地址通过解析捕获 APDU，检查长度与 I 帧发送序号连续性；重连按新会话检查。记录 I/S/U 帧数量；已有回归覆盖无效长度、窗口参数、双点和步位置信息。

已确认的边界与后续改进方向

实时状态与事件历史需要分别验收。 当前 C 通过 collect_once() 读取底层最新点值；S 与 T 通过周期扫描数据库对比状态。如果一个点在相邻扫描之间发生多次改变，中间状态可能被合并。21 次线上变位只返回一个采集快照的独立用例已验证这一边界。

需要逐条 SOE 时，应增加接收事件队列与持久化事件记录，并在转发链路保留源时间、质量、事件顺序及溢出诊断，再按事件计数校验完整性。该能力没有在本轮作为新增功能实现。

效率方面，批量 ASDU 已明显降低报文数量；完整链路仍受 S 扫描、C 快照周期、写库等待及 T 扫描共同影响。后续优化宜分别测量各阶段，重点验证批量写库的最大等待时间及持续小批流量，避免只看单次总召速度。

本轮未覆盖物理设备互操作、广域网延迟/丢包、持续高负载下的 CPU/内存曲线、长时间稳定性、全部异常序号场景，也未据此宣称通过完整 IEC104 一致性认证。
