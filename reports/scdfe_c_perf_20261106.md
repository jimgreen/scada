# scdfe_c 效率复测 · 2026-11-06

以 `cf95288` 为基线，在同一台 Windows 主机、同一 Python 虚拟环境下测试。性能测试使用实际业务库的在线备份，未在业务点上执行基准写入。业务库有 63 个 RTU、遥测和遥信各 60,002 点、遥调和遥控各 12,002 点。下表为七轮预热后重复调用的中位耗时；规约项测的是建站配置加载，不是现场网络时延，Web 项测的是服务端统计，不是整页加载。

| 操作 | 优化前 | 优化后 | 耗时减少 |
|---|---:|---:|---:|
| Web 顶部五项计数 | 2.407 ms | 1.260 ms | 47.6% |
| 建立 BACnet 主站（2,400 点） | 17.201 ms | 11.285 ms | 34.4% |
| 建立 OPC UA 主站（2,400 点） | 18.632 ms | 11.725 ms | 37.1% |
| 更新一条 RTU 配置 | 0.0667 ms | 0.0426 ms | 36.1% |
| 小时日志读末尾 200 行 | 4.853 ms | 0.305 ms | 93.7% |
| 小时日志读末尾 5,000 行 | 5.041 ms | 1.024 ms | 79.7% |
| 写 2,000 条 64 字节报文，每条刷新 | 31.037 ms | 24.402 ms | 21.4% |

**数据库和规约。** 七类可以改属 RTU 的规约配置表，原先只改归属时不会递增任一 RTU 的配置版本。修复后，旧站和新站各递增一次，不变的保存不触发重载，同时修改归属和名称也不会重复通知。只需字段级校验的表把版本条件直接交给 UPDATE；Modbus 和转发配置仍在锁内校验整行。旧版 OPC UA 和 BACnet 建站分别读取两次映射；现在配置、点和地址出自同一 SQLite 快照，每次建站的 SELECT 从 8 条降为 3 条。两套各 2,400 点，结果摘要与基线一致。IEC104、Modbus TCP/RTU、CAN 的规约行为由完整回归覆盖，本轮不宣称它们的线上收发加速。

**索引取舍。** 在副本中逐一移除三个旧 Modbus RTU 索引再回滚。对 call、data、ytyk 按 RTU 查并按 ID 排序，原计划均可直接使用覆盖索引；移除后均增加临时排序。保留这些索引，没有重建业务表。查询计划见[测量数据](scdfe_c_perf_20261106.json)。

**日志和界面。** 读取日志尾部改为从文件末尾分块读，保留原 2 MB 上限、多字节字符、空行和截断标志。样本为 13 万行 UTF-8 小时文件；1、200、5,000 行结果摘要均与基线相同。日志写入保留逐条刷新，并在写锁内取本地时间；午夜轮转、前后两小时的文件和即时可见性均已验证。Web 摘要只查屏幕需要的五张表，原全量 API 保留。完整总览修复了只统计前 500 个 RTU 的问题；实测 571 站，浏览器可在第二页选择 RTU 91507，手动刷新后仍显示其遥测值 908.5，并能筛出单方向报文。

**回归与原端口。** 共 469 项，468 项通过、0 项失败、1 项因 Windows 无创建符号链接权限跳过，用时 236.674 秒。三服务联动用例包含遥测、遥信、遥控、遥调，以及完整启停；本轮没有重做上一轮的 30 分钟耐久测试。新版本在 8877 进行了 60 次并发只读请求，并用真实浏览器切换 RTU 2、3 及日志页面。业务库与上线前备份的 28 张表双向比对一致，仅排除在运行的 T 转发进程的瞬时字段和行版本；DDL 差异只有预期的七个版本触发器，完整性检查为 ok，外键错误 0。原 C 三个后台角色保持停止，T 通道 1 的进程未更换。
