# SCDFE C/S/T Web 与 HMI 优化复测（2026-11-10）

本轮针对 S/T 的通信监控页面和聚合状态读取进行了优化，C 端沿用同一工作目录中已验证的采集热路径结果。测试使用隔离临时 SQLite、20 个通道、HTTP/1.1 长连接、12 轮测量并丢弃前 2 轮预热值。

| 模块 | 场景 | 优化前 | 优化后 | 结果 |
|---|---|---:|---:|---:|
| scdfe_s | 通信监控一次刷新耗时 | 5.9003 ms | 5.2208 ms | 下降 11.52% |
| scdfe_s | 一次刷新 HTTP 请求数 | 3 | 2 | 减少 33.33% |
| scdfe_s | 一次刷新响应字节 | 41891.5 | 41267.0 | 减少 1.49% |
| scdfe_t | 通信状态读取耗时 | 3.9127 ms | 0.8977 ms | 下降 77.05% |
| scdfe_c | YC 缩放热路径（changed） | 1838.713 ms | 1745.693 ms | 下降 5.06% |
| scdfe_c | 采集管线 | 5219.577 ms | 952.245 ms | 下降 81.76% |

S 端前端不再在聚合通信接口之后按规约重复请求独立状态，后端也把每个 RTU 的通道关系查询合并为一次读取。T 端通信页使用已有的 `/api/trans/status` 统一投影，因此可以显示连接状态、收发/错误计数、心跳和诊断字段，同时避免每次刷新执行进程租约检查。T 端增加了请求互斥和相同表格内容跳过 DOM 重绘。

T 端优化后的响应更大，是因为页面新增了诊断快照；本轮以延迟和功能完整性为主要指标，不能把响应字节增加解读为性能退化。

验证结果：定向测试 20 项通过，全量测试 `515 passed, 1 skipped, 403 subtests passed`；Python 编译、JavaScript 语法和 `git diff --check` 通过。隔离临时 S/T 页面已在浏览器中打开并检查了通道状态表，未重启 8877/8878/8879 正式服务。
