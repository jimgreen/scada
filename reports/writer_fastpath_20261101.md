# 批写参数准备快路径效率对比（2026-11-01，第 4 轮）

本轮相对于 `71444c2` 优化独立写库进程的参数准备。最终代码先测三次，再因单次耗时波动追加四次；两组运行时代码 SHA-256 完全一致。以下统计包含全部七次结果，没有剔除较慢运行，也没有将前期候选代码的结果混入最终统计。

## 完整写回效率

| RTU 数 | 点更新次数/运行 | 优化前中位数 | 优化后中位数 | 耗时减少 | 吞吐：前 → 后 | 吞吐提升 |
|---:|---:|---:|---:|---:|---:|---:|
| 6 | 240,000 | 0.923 s | 0.897 s | 2.82% | 260,056 → 267,602 次/s | 2.90% |
| 60 | 2,400,000 | 8.859 s | 8.368 s | 5.55% | 270,899 → 286,804 次/s | 5.87% |

这里的吞吐提升是优化前后吞吐之比减一，耗时减少是耗时差除以优化前耗时，两者口径不同。本次重新测量基线，不与历史报告在其他时段的绝对数值直接计算累计加速比。

## 修改内容

- 单条消息且主键顺序规范、点键不重复时，校验后直接按 SQL 分组保留参数元组，省去每点合并字典和后续重新分组。
- 重复键、非规范主键顺序以及多消息批次沿用通用合并路径，保留最后字段值、部分字段累加和每次合并写回只递增一次 `_version` 的规则。不同表、主键字段和 RTU 仍分别识别。
- 快路径和通用路径共用分组元数据校验；行长度、不可哈希主键、非法 SQL 标识符仍会导致整批失败。所有准备发生在事务前。
- 保持 WAL、`synchronous=NORMAL`、事务提交/回滚、锁重试、队列确认、通信线程异常隔离以及独立 spawn 写库进程。消息格式、批间隔和批大小均未调整。

## 负载与计时口径

- 每种规模包含 IEC104、Modbus TCP、Modbus RTU、CAN、BACnet、OPC 各 1/10 站；每站 YC1000、YX1000、YK200、YT200。60 站共 144000 个四遥点，其中 YC/YX 共 120000 点。
- 每站 20 周期，每周期 2000 个 YC/YX 值全部变化；遥控/遥调定义已建，但本基准不下发命令。
- 每 RTU 一个通信生产线程，共享容量 64 的 JoinableQueue；独立 spawn 写库进程，批间隔 0.2 秒、max_batch=500。每条 2000 点消息单独触发一次事务。
- 计时包含模拟测量对象生成、通信线程处理、消息构造与序列化、IPC、SQLite 更新/提交以及写库进程排空退出；不含数据库准备、进程启动和最终核验。
- 冻结前后源码，父子进程核验 SHA-256；独占基准锁、串行执行，每个文件内偶数重复反转版本顺序。追加四次用于检查最初三次中的波动。
- Windows 10 build 26200、Python 3.11.15、SQLite 3.53.1；仅临时数据库，无现场设备连接。正式 `db/scada.sqlite3` 未参与压测。

## 波动和适用边界

- 6 RTU：优化前范围 0.897–0.943 秒，优化后 0.881–0.947 秒；平均耗时 0.921 → 0.902 秒，减少 2.05%。
- 60 RTU：优化前范围 8.640–12.479 秒，优化后 8.230–10.429 秒；平均耗时 9.434 → 8.852 秒，减少 6.17%。
- 60 RTU 第 1 次优化后慢于优化前约 13.2%；6 RTU 也有较慢运行。结果支持典型吞吐有小幅改善，不表示每次都更快或最坏延迟得到保证。
- 60 站按中位数折算每轮 120000 点写回约 0.418 秒。这是离线模拟数据的数据库写回能力，不是六种规约实际设备采集周期。
- 代码继续使用跨平台 Python/SQLite API，无新增 Windows 专用依赖；Linux 本轮尚未实机执行。

## 正确性与回归

- 28 次完整运行，共 36960000 次点更新；累计逐行核验 1848000 行最终状态，值均对应各站最后周期、status=0、`_version=21`。
- 所有运行 `integrity_check=ok`、外键违规为 0、写库进程退出码为 0。前后每条 2000 点消息均为 96790 字节。
- 新增 3 项回归：单分组内重复点与部分覆盖、跨分组重复键、同 SQL 的列表/元组参数以及跨表跨站隔离。保留原有整批回滚、非法参数、锁重试、队列失败重试和测量心跳测试。
- 最终 `unittest discover -s tests -q`：92 项通过；`web.test_server web.test_protocol_seed_data`：21 项通过；Ruff、py_compile、git diff --check 通过。
- 测试仍输出 UDP/asyncio 资源释放和 Web 子进程仍在运行的 ResourceWarning；故障注入测试产生预期写库进程异常堆栈。通过结果不代表这些既有资源清理警告已解决。
