# scdfe_c / scdfe_s / scdfe_t 多通道并发与原端口验证

2026-11-06，Windows，本地工作树以 `e7a92e9` 为基线。35 分钟持续收发、4 分钟并发写故障注入、完整回归和原端口验证通过。两类问题均在修复前复现，并在修复后用同一负载或同一操作验证。

## 修复与前后对照

**同步建连时拒绝连接。** 三个 Web 监听器及 C 的写入、命令监听器原本使用很小的默认等待队列。将待接受的 TCP 连接数设置为 128，保持已有的写入并发控制、超时及提交确认语义。下表每行独立执行 48 个客户端同时连接、重复 3 轮；耗时是整次调用的第 95 百分位，包含失败样本。写入和命令端点成功后还逐点读回 SQLite，核对值和命令时间。

**Web 选错通道。** 两个相邻 ID `9007199254740992` 和 `9007199254740993` 超过 JavaScript 安全整数上限；S 还只读前 500 条。访问第二个 ID 时，旧 S 页面选中厂站 1，旧 T 页面选中第一个 ID。现在 S 分页取得全部候选，S/T 用精确 ID 选择通道、编辑和保存。实测 S 的 507 个候选全部可选；分别在 S/T 修改第二个通道的测点后，通过 API 确认第一个通道原值未变。另验证 C 可以选择第二个 ID。见[浏览器前后对照](scdfe_concurrency_20261106/browser.json)。

## 完整回归与原端口

- 全部回归共 478 项，477 通过、0 失败、1 跳过，耗时 230.946 秒。唯一跳过项是测试环境没有创建 Windows 符号链接的权限（WinError 1314）。见[原始回归输出](scdfe_concurrency_20261106/full_regression.txt)。
- 完成回归后只重启三个 Web。8877、8878、8879 各做一次 48 客户端同步健康访问，全部成功，P95 分别为 34.86、36.31、34.77 ms。另在 8879 完成 84 次并发读请求。在三个原端口均验证已有文件的 RX/TX 报文方向筛选。
- 真实浏览器通过原端口验证 C 的 RTU 切换、S 刷新保留未保存编辑、T 通道 1 日志的 RX/TX 筛选。T 工作者 PID 17736、监听端口 2404 未变；IEC 104 总召读回遥测 42.0、遥信 false，两者质量码均为 0，和原库一致。C 三个角色及 S 九项规约服务仍保持各自原启停状态。
- 原库与测试前在线备份对照：表结构相同，28 张表的业务数据未变（排除 T 运行心跳、进程元数据及其版本号）；SQLite 完整性正常、无外键错误。未为原端口开启报文保存；T 报文筛选使用已有文件。见[原端口明细](scdfe_concurrency_20261106/original_ports.json)。
