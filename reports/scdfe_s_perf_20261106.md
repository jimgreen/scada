# scdfe_s 性能与交互验证 · 2026-11-06

## 改动与收益

S 的规约页只请求界面实际显示的点字段；外部调用不指定 `view=table` 时，仍返回完整点定义。IEC104 用一次读事务内的左连接取得四遥和地址映射，保留无映射的点。其他规约的单点接口按 RTU 和点号直接查询，不再读取该类型的所有点；读点不再顺便查询规约参数。点值快照只复制标量字段，不逐点递归拷贝。切换 RTU 与同时采样时，同一次读取使用同一组采样值。

使用当日正式库的同一份 SQLite 在线备份，在临时库中测量。表格每次 2400 点；各项先预热，取 5 组计时的中位数。HTTP 指标包含本机请求和返回数据，写入及快照指标是应用层调用。时间受主机负载影响，不代表现场周期或保证上限。

|---|---:|---:|---:|
| IEC104 点表 HTTP | 99.023 | 23.472 | 76.3% |
| Modbus TCP 服务端点表 HTTP | 87.307 | 25.863 | 70.4% |
| Modbus TCP 单点 HTTP | 34.868 | 3.842 | 89.0% |

两张点表的 UI 字段逐行摘要前后一致，单点的完整返回值一致。IEC104 响应体从 2,060,698 降至 252,315 字节，Modbus 从 1,756,493 降至 263,846 字节。150 条报文计时开启了调试保存；900 条累计写入均可立即读出。该项测量的是应用写入并刷新到操作系统的时间，没有逐条强制磁盘同步。

## 数据库、规约与日志

- 没有改正式表结构。SQLite 的单点计划直接使用 `fes_yc_define` 的复合主键；IEC104 查询在点表上按主键查 RTU，在映射表上用已有唯一索引查 RTU、种类和点号，无需维护第二个相同用途的索引。
- 绑定数据库 RTU 的 CAN、OPC UA、BACnet 服务端：先校验整批，再一次提交，最后向规约端发布。针对三种服务分别在第二点注入数据库错误，第一点也回滚，规约值不变。另验证提交成功后规约发布失败的情况：返回明确错误并保留已提交的数据库值。逐点规约发布不保证整批在同一瞬间可见。
- 独立客户端经本机 TCP 连接，在临时库上并发运行 40.08 秒。OPC UA 完成 884 轮、Modbus TCP 完成 927 轮，每轮批量写两点，再独立读取协议端、Web 和 SQLite 核对。两种协议各注入一次事务失败，拒绝后客户端和 Web 均保留原值。未连接外部 PLC、物理 CAN 总线或串口；其他协议按回归覆盖的模拟、虚拟总线或回环场景验证。
- 协议运行期间复用当前小时的日志句柄，写完即刷新，停服释放。验证了单通道开关开启后的报文可从文件读回、关闭后的报文只在即时记录可见、停服后的文件可改名。正式服务保持默认关闭报文保存。原端口的日志页检出 108 个文件；在所有文件中先后按 RX、TX 筛选，每种各显示 200 条，逐行检查了方向。

- 自动化回归：474 项，耗时 257.517 秒，473 项通过、1 项因 Windows 缺少创建符号链接权限跳过，0 项失败。第一轮发现的 RTU 切换时采样叠加错误已修复；轮询测试的模拟 DOM 同步更新，并断言刷新前后仍是同一行。
