# IEC104、MODBUS、CAN 与数据库读写优化复核（2026-11-07）

本轮在 `D:\\codex\\scada` 继续复核并验证 IEC 60870-5-104、MODBUS-RTU、MODBUS-TCP、CAN 以及 SQLite 数据库读写路径。工作区已有修改全部保留，没有执行 reset、clean、提交或推送。

## 已落地的优化

- MODBUS-RTU/TCP 在配置阶段预构建轮询计划，采集阶段直接调用已选定的底层 `_invoke`，避免每轮重复功能码映射、地址范围校验和公共 API 分发；从站号、功能码、请求边界和响应数量校验保持原语义。
- IEC104 保留点对象、类型转换器和单轮统一时间戳复用，减少轮询期间重复构造；启动、总召唤、确认和监视量更新顺序不变。
- CAN 保留帧索引、位域解码和命令帧复用。候选解码优化经过重复基准没有稳定收益，因此没有引入会增加风险的改动。
- `ScadaStore` 缓存不可变表元数据、主键、字段映射和文本筛选列；连接归还连接池时仅在存在未提交事务时执行 `rollback()`，减少普通只读请求的无效调用。

MODBUS、IEC104、CAN 的协议语义优先于未经现场设备验证的并发请求；因此没有把可能改变设备负载、报文顺序或超时行为的 BACnet/IEC104 并发候选合入。

数据库表元数据缓存的独立 `list_rows` 基准此前为 352.2005 ms 降至 347.9106 ms（约 1.22%）；本轮连接池 rollback 条件化属于低风险微优化，单次只读基准未显示稳定收益，因此不把它宣传为确定的吞吐提升。
