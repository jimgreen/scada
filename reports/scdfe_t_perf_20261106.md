# scdfe_t 转发效率与现场端口验证 · 2026-11-06

## 检查结果和改动

T 实际提供 IEC104 和 Modbus TCP 两类转发。检查了 SQLite 源点读取、两类规约的发布与命令路径、通道与点映射 Web、日志文件写入策略、尾读及筛选。所有性能实验和业务写入在临时库中进行；原库只作备份、只读比对和正常启停状态登记。

| 本机测量场景 | 之前 | 之后 | 耗时降幅 |
|---|---:|---:|---:|
| 扫描同一 RTU 的 2400 个连续源点（含质量） | 2.523 ms | 1.671 ms | 33.8% |
| 从上述 RTU 读取 100 个稀疏源点 | 0.118 ms | 0.100 ms | 15.3% |
| 完整读取 1200 条通道定义 | 5.569 ms | 4.974 ms | 10.7% |
| 从超过 2 MB 的报文文件读取最后 3 行 | 5.584 ms | 0.428 ms | 92.3% |

基准用相同数据生成临时库，预热后取 5 组计时中位数；同一场景优化前后的完整返回值摘要一致。这是本机应用耗时，不是现场端到端时限。另在新版对比两种 HTTP 响应：1200 个通道的完整列表为 529,490 字节、16.493 ms；四遥页选择器为 101,090 字节、4.162 ms，四个供显示的字段逐行相同。

- **数据库结构和读取。** 源点连续时使用现有主键 `(rtu_id,pnt_no)` 的范围扫描；稀疏点使用精确点号，重复映射仍可扇出到不同转发点。跨 RTU 和分批查询保留同一读事务。全通道/全点映射读取改为单次快照，避免多页计数和跨页期间数据变化。正式库查询计划显示源点与转发表都命中已有主键或索引，因此本轮未增加、迁移或删除表和索引。
- **规约通信和存储。** 运行中的 Modbus 把一轮变化值交给事件循环处理，扫描线程等待时不持有远端命令所需的锁；启动时不重复发布初值。编码失败的点不提前修改本地缓存，其他点继续发布，失败点下轮重试。IEC104 仍发送质量变化，遥控、遥调仍由 C 写库进程处理。本轮没有改变命令确认或数据库持久化策略。
- **日志。** 保持按小时写文件、默认关闭报文保存、可按通道开启的策略。大文件尾读改为从末尾分块读取；小文件保留准确总行数。T 的目录和检索接受 `channel_id`，按文件所属通道选取，不依赖报文文本。验证通道 1 不混入通道 10，文件在没有报文通道标记时也能与 RX/TX 条件组合筛选。
- **Web。** 四遥页只取选择框所需的通道字段。相同映射在刷新时保留原行和按钮；可见值和版本号变化时更新对应单元格及删除操作的版本号，删除或切换通道时仍会清除旧行。

## 验证

- 最终自动回归 477 项，用时 229.342 秒。476 项通过，0 项失败；1 项因 Windows 缺少创建符号链接的权限跳过。覆盖协议命令、进程启停、点映射、日志分页与三套系统交互。
- 临时库同时启动两个受管理的 T 进程，分别使用 IEC104 和 Modbus TCP。42.4 秒内提交 706 批双点数据；独立客户端完成 2820 次 Modbus 双寄存器读取、693 次 IEC104 总召，同时完成 141 轮 Web 状态与通道选择器检查。Modbus 每次均读到成对的同代值；最后两端读回 746、747，IEC104 最终质量为 0。两通道各检出 RX、TX 报文。没有对现场设备发送控制命令。
- 浏览器隔离验证：通过编辑页保存点名，数据库读回新值，另一通道未变化；原行及按钮保留，版本号前进。切换通道及筛选空点类型后显示正确。
- 在确认 2404 没有活动客户端后，更新原 8879 Web，并协作停启 IEC104 通道 1，恢复原启用状态。原 2404 总召读回 YC1=42、YX1=0，二者质量码为 0，与数据库对应点一致。在原 8879 上，刷新四遥页面由替换全部 4 行变为保留 4 行，编辑焦点不丢失；通道 1 的历史日志筛选分别展示 88 条 RX 和 150 条 TX，逐行核对了通道及方向。
- 8 个并发请求线程完成 84 次原端口只读 HTTP 请求。8877、8878、8879 均健康。原库与在线备份的 SQL 定义完全相同；28 张表的业务数据双向比对一致，T 的进程状态和版本号不参加业务数据比对。完整性检查为 `ok`，外键错误 0。
- 协议验证使用本机真实 TCP 连接；不代表已验证外部主站、现场链路或长期无人值守运行。
