# 三服务多通道并发验证 · 2026-11-06

Windows 本机实测。主测试使用独立的源站数据库和采集/转发数据库、动态监听端口、真实 Modbus TCP 和 IEC104 客户端，不写业务点值。原端口复验单独列出。结果为本次窗口内的观测，不代表 24 小时或现场链路认证。

## 修复与效果

- scdfe_s Modbus 从站的一次 Web 批量更新现在先校验，随后一次提交数据库，再在规约线程一次性发布。通过触发器拒绝第二个点、非法寄存器值、重复点号、同一物理寄存器的矛盾值等故障注入验证，失败时两个寄存器及两行数据均保持原状。若数据库已提交但发布未确认，接口明确反馈该状态。
- 读取不同类型的点值使用同一 SQLite 快照；IEC104 映射按类型和点号匹配，页面显示 IOA 和类型标识。原 8878 的 RTU 2 有 2400 条映射，此前返回 0 条有效地址，部署后 2400 条与 SQLite 完全一致。
- scdfe_s 配置页的定时刷新不覆盖未保存的输入，保存过程中继续修改的字段也保留。真实浏览器验证手动刷新、5 秒轮询、延迟响应、实际保存并重载。2,400 行静态点表刷新时，删除/重建的行数从 2,400 降为 0；持续变值时保留行且更新相应值。

源库和采集库均通过完整性及外键检查。每分钟采样一次，采集库 WAL 为 1.34–3.95 MiB，四个转发进程未更换 PID。资源为采样值，不能据此排除更长运行周期内的泄漏。

底层 Modbus 库输出 3 次“连接已关闭，取消发送”。原日志没有连接标识，无法逐次归因。单独故障注入：60 个客户端发出请求后立即断开，复现 50 次相同提示；同时另一长连接 60 次读取全部正确，未重连。这里不将底层日志宣称为零告警。

- 三个独立写入线程并发 16,966 次三点更新，夹入 1,023 次预期拒绝。独立 TCP、SQLite、Web 读者分别完成 18,456、19,242、9,706 次读取，未见半批或失败批次暴露。
